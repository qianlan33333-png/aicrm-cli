# v0.1.2

新增专用群运营 Webhook 客户端：

- `group-ops webhook configure`：隐藏输入或 protected stdin，将当前 Origin 的 HMAC 密钥保存到独立系统密钥环。
- `group-ops webhook status/forget`：本机配置检查和删除，不覆盖既有人类/机器登录。
- `group-ops webhook send --input FILE --event-id ID [--dry-run]`：沿当前 V4 协议签名并提交动态群运营消息。
- `schema webhook`：查看请求结构、签名头、消息与重放规则。

签名与发送保持请求文件的原始 UTF-8 JSON 字节，使用调用方显式稳定事件 ID。HTTPS Origin 精确绑定；拒绝重定向；写请求不自动重试。明确 Owner 拒绝保留安全错误码，超时、连接丢失、响应不完整或非合同响应返回结果未知及退出码 7。

支持首条可选文字，以及最多九个图片、文件、小程序附件（最多一个小程序）。目标须为当前启用 Webhook 计划的绑定群；权限、素材与 Provider 条件继续由服务端验证。HTTP 202 表示任务受理，现有企微企业群发仍需要运营成员确认，最终投递另行查询。

现有 564 项服务端目录（512 human、20 machine、32 无执行绑定）及 54 项群运营管理接口不变。Webhook 客户端使用独立 HMAC 身份，不转换人类或机器权限。没有服务端部署、数据库迁移或真实群发。

28 项客户端测试通过，含 9 项新增签名、原始字节/事件重放、凭据隔离、重定向拒绝、输入/素材结构、错误与未知结果、断连/超时不重试及协议发现用例，无失败或跳过的测试。发行覆盖 Mac/Linux arm64 与 amd64、Windows amd64，归档 SHA-256 位于 `checksums.txt`。

完整安装、环境、素材、发送、查询与重放步骤见 [Webhook 使用说明书](../groupops-webhook.md)。

```sh
go install github.com/qianlan33333-png/aicrm-cli/cmd/aicrm-cli@v0.1.2
aicrm-cli group-ops webhook configure
aicrm-cli schema webhook
aicrm-cli group-ops webhook send --input groupops-request.json --event-id YOUR_STABLE_EVENT_ID --dry-run
```
